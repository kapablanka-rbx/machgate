## Fix 1 — kevent struct size mismatch (108+ crashes)

**Symptom**: `RbxTransportProtocol.UnitTest` SIGSEGV at
`SysEventLoop::processPendingIoCallbacks+0x54`. `ev->h` = 0x5ffff (garbage
handle pointer). Suspected stale kqueue udata delivery.

**Root cause**: `darwin_kevent_placeholder` was 48 bytes (with `uint64_t
ext[2]`). The real Darwin `struct kevent` (from macOS SDK
`sys/event.h:86-93`) is 32 bytes — `ext[2]` only exists in
`struct kevent64_s` (48 bytes), a separate API. The shim wrote events at
48-byte stride; the engine read at 32-byte stride. With 2 events, the
engine's `udata` field landed on shim event 1's `filter` + `flags` +
`fflags` bytes = `0x0000000005FFFF` = exactly the garbage crash value.

Commit `912137e` added `ext[2]` claiming "stack smashing gone" — that was a
misdiagnosis. The stack smashing was caused by the same stride mismatch
(the shim overwrote past the guest's stack-allocated eventlist). The
SO_SNDBUF socket option mapping in the same commit was correct and is
preserved.

**Fix**: Removed `ext[2]`, added `#pragma pack(4)` to match the SDK layout
exactly.

**File**: `src/shim/libsystem_shim.c:8921`

**Verification**: `QuicCidLifecycle/server_close_unregisters_cids_from_dispatcher`
passes (11 assertions). 22 tests across QuicCidLifecycle, QuicStreamSocket,
QuicDispatchHandler, SendChannelTests, SystemTests — all pass (114
assertions).

**Impact**: 108 crashes in RbxTransportProtocol, 48 in FbxImport, and likely
many more across all kqueue-using drivers.

## Fix 2 — pasteboard ObjC string stub (283 crashes)

**Symptom**: AssetImport (104), AssetImportIntegration (112), FbxImport
(48), AssetImportSdk (19) — all crash during static init with SIGSEGV.

**Root cause**: `_NSPasteboardTypeString` resolved to `&ns_pasteboard_type_string`
where `ns_pasteboard_type_string = NULL`. The guest treats this as an
NSString object, dereferences NULL, SIGSEGV.

**Fix**: `resolve_non_gui_framework_data` in `resolver.c:641` now returns a
pointer to a properly formatted `shim_objc_string` object carrying
`"public.utf8-plain-text"` (the UTI that NSPasteboardTypeString represents).
The shim's `objc_msgSend` recognizes the object by its magic/kind header and
returns the inline UTF8 text for `UTF8String` selector calls.

**File**: `src/resolver.c:641`

**Verification**: App_Group.UnitTest loads past the pasteboard static init
that previously SIGSEGV'd.

**Impact**: 283 crashes across 4 drivers.

## Fix 3 — gateway kevent no-op (1151+ timeouts)

**Symptom**: Network.UnitTest (1023 timeouts), Http.UnitTest (128 timeouts).
Tests hang indefinitely on socket event loops.

**Root cause**: `handle_kevent_noop_wait` in
`src/syscall/syscall_range_200_399.c:4587` returned `ENOSYS` for any kevent
call with actual changes or events. The shim has a working kqueue/kevent
implementation (using `poll()`), but statically-linked guest code goes
through the syscall gateway, not the shim.

**Fix**: Replaced the no-op handlers with handlers that delegate to the
shim's `kqueue()`, `kevent()`, and `kevent64()` functions via `dlsym`. Added
`#include <dlfcn.h>`. Cached function pointers in static locals. Updated
dispatch cases for kqueue (362), kevent (363), kevent64 (369), kevent_qos
(374, stubbed to basic kevent), kevent_id (375, stubbed to basic kevent).

**File**: `src/syscall/syscall_range_200_399.c`

**Verification**: Network.UnitTest `TrackerDataReplicationTest`,
`StreamingPinTest`, `TraceRouteService` — all pass (previously timed out).

**Impact**: 1151+ timeouts across Network, Http, and other socket-heavy
drivers.

## Fix 4 — dispatch_async runs inline (534+ timeouts)

**Symptom**: App.Economy (214 timeouts), ScriptServices (160 timeouts),
App.Communication (160 timeouts). Tests deadlock on `std::future::get()`
and `pthread_cond_wait`.

**Root cause**: `dispatch_async` in `libsystem_shim.c:10848` ran blocks
synchronously inline (`dispatch_invoke_block(block)`), ignoring the queue
parameter. Any code relying on GCD for producer-consumer patterns, lock
avoidance, or thread-context separation deadlocked.

**Fix**: Implemented a real thread pool for `dispatch_async`. On first call,
spawns 4 detached worker threads via `dlsym(RTLD_NEXT, "pthread_create")`.
Uses a mutex + condition variable + linked list of work items.
`dispatch_async` enqueues and signals; workers dequeue and invoke.
`dispatch_sync` stays inline (correct behavior).

**File**: `src/shim/libsystem_shim.c:10848`

**Verification**: `MarketplaceApiClientTests/PerformPurchase_GamePass_SendsCorrectJson`
passes (3 assertions, 35ms) — previously hung indefinitely.

**Impact**: 534+ timeouts across App.Economy, ScriptServices,
App.Communication, and likely many more GCD-dependent drivers.

## Fix 4b — pipe() non-blocking by default

**Symptom**: Http.UnitTest worker threads block on drain reads of pipe fds.

**Root cause**: `shim_pipe` called `syscall(SYS_pipe2, pipefd, 0)` — no
`O_NONBLOCK`. Darwin's `pipe()` creates non-blocking pipes by default for
GCD usage. The `fcntl(F_SETFL, 0)` call from guest code didn't set
`O_NONBLOCK` (arg=0 clears flags).

**Fix**: `shim_pipe` now calls `syscall(SYS_pipe2, pipefd, O_NONBLOCK)`.

**File**: `src/shim/libsystem_shim.c:11898`

**Verification**: Http tests no longer hang on pipe drain reads.

## Fix 5 — ASan data symbols (all ASan builds)

**Symptom**: All ASan-built binaries SIGSEGV during the 3rd static
constructor (`__cxa_guard_acquire+0xa0`). The crash instruction is
`stp x8, x9, [x26]` where x26 = garbage shadow address.

**Root cause**: `libclang_rt.asan_osx_dynamic.dylib` is not in the dylib_map,
so it's classified as `DYLIB_SKIP`. All bindings — including two critical
DATA symbols — resolve to `alloc_return0_stub()` (code at 0x52800000 +
0xd65f03c0). The guest reads the stub's machine code bytes as data:
- `___asan_shadow_memory_dynamic_address` → 0xd65f03c052800000 (garbage
  shadow base) → SIGSEGV on shadow poisoning
- `___asan_option_detect_stack_use_after_return` → 0x52800000 (non-zero)
  → enables fake-stack allocation (wrong)

**Fix**: Extended `resolve_non_gui_framework_data` in `resolver.c:641` to
handle ASan data symbols. `___asan_shadow_memory_dynamic_address` returns a
pointer to a `uintptr_t` holding the base of a 512MB mmap'd shadow region
(`MAP_ANONYMOUS | MAP_PRIVATE | MAP_NORESERVE`).
`___asan_option_detect_stack_use_after_return` returns a pointer to a zero
`uint32_t` (disables fake-stack). All other `___asan_*` function symbols
continue to resolve to the return-0 stub (correct no-op).

**File**: `src/resolver.c:650`

**Verification**: Cannot test locally with `sanitize=none` corpus (no ASan
dylib). Build succeeds. LLVM compiler-rt source verified: shadow scale is
1:8, 512MB covers 4GB guest VA, `detect_stack_use_after_return=0` disables
fake-stack.

**Impact**: Unblocks all ASan-built test binaries.

## Fix 6 — psynch_cvwait zero timeout (busy-loop spinning)

**Symptom**: Threads spin on `FUTEX_WAIT_PRIVATE` with immediate
`ETIMEDOUT`, causing high CPU usage and contributing to test timeouts.

**Root cause**: `handle_psynch_wait_probe` in
`src/syscall/syscall_range_200_399.c:4087` hardcoded
`struct timespec timeout = {0, 0}`. On Linux, `FUTEX_WAIT` with `{0,0}`
returns immediately with `ETIMEDOUT`. On Darwin, `{0,0}` means "no timeout"
(wait forever). Every `pthread_cond_wait` (no timeout) passed `{0,0}`,
futex returned `ETIMEDOUT` instantly, and the loop spun.

**Fix**: Extract timeout from guest registers x4 (seconds) and x5
(nanoseconds) — these are a relative timespec per the XNU
`__psynch_cvwait` ABI. Pass `NULL` timeout for infinite wait when both are
zero. Handle expired deadlines (sec < 0) with a zero timespec. Removed the
incorrect `ETIMEDOUT → EAGAIN` errno mapping (Darwin returns ETIMEDOUT, not
EAGAIN).

**File**: `src/syscall/syscall_range_200_399.c:4087`

**Verification**: 32/33 machgate tests pass — no regressions.
