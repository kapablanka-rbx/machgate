# MachGate Rotest Integration — Glossary

This glossary extends the rotest scheduler glossary
(`Client/BuildScripts/rotest/librotest/scheduler/docs/GLOSSARY.md`) with
MachGate-specific terms. The MachGate integration is a **ProcessLauncher**
variant — it changes how an Executable is launched, not the domain concepts
of TestGroup, Worker, or Scheduler.

## Core terms

| Term | Definition | It is not |
|---|---|---|
| **MachGate** | The runtime that loads and executes ARM64 Mach-O binaries on Linux by translating the Darwin ABI surface (syscalls, dylibs, C++ runtime). | An emulator. A virtual machine. A container runtime. |
| **Guest binary** | A macOS or iOS ARM64 Mach-O executable that MachGate loads and runs. Same as a rotest Executable — MachGate does not introduce a new domain concept. | A Linux ELF binary. A Docker image. |
| **MachGate wrapper** | The `machgate` command-line binary that wraps a guest binary: `machgate /path/to/guest.UnitTest --args`. It is the ProcessLauncher's entry point. | A test framework adapter. A Driver Format. |
| **MachGate mode** | The rotest platform mode activated by `--machgate`. Parallel to `--android` and `--ios`. It determines how test binaries are launched. | A scheduler mode. A worker mode. A test framework. |

## Execution environment

| Term | Definition | It is not |
|---|---|---|
| **Native ARM64 host** | An ARM64 Linux machine where MachGate runs guest binaries directly — `machgate /path/to/test`. No QEMU, no Docker. The fast path. | A Mac. An x86_64 machine. |
| **QEMU host** | An x86_64 Linux machine that runs ARM64 binaries via QEMU/binfmt. MachGate works but is 10-50x slower. rotest `--machgate` mode detects this and adjusts. | A native ARM64 host. |
| **MachGate container** | An ARM64 Docker image with MachGate, `libsystem_shim.so`, and Apple-ABI `libc++.so.1` pre-installed. Used on QEMU hosts to provide a consistent ARM64 Linux environment. Required on x86_64, optional on ARM64. | The guest binary. The test framework. |
| **MachGate prefix** | The command prefix that `make_executable_launch_command()` returns for machgate mode. On ARM64: `["machgate"]`. On x86_64: `["docker", "run", "--rm", "--platform", "linux/arm64", "machgate-runner", "machgate"]`. Parallel to the ADB prefix for Android. | A Driver invocation. A TestGroup. |

## MachGate runtime components

| Term | Definition |
|---|---|
| **libsystem_shim.so** | Shared library that maps Apple `libSystem.B.dylib` symbols to glibc equivalents. Loaded as the dylib map target for `libSystem.B`, `CoreFoundation`, `CoreServices`, `Security`, `IOKit`, `libresolv`, `libicucore`. |
| **Apple-ABI libc++** | A `libc++.so.1` built with `_LIBCPP_ABI_ALTERNATE_STRING_LAYOUT` so `std::string` matches Apple's memory layout. Required for C++ guest binaries. Built from the LLVM submodule via `scripts/build-libcxx.sh`. |
| **dylib_map.conf** | Configuration file that maps macOS dylib names to Linux equivalents or actions (STUB, SKIP). Generated by rotest at initialization. |
| **machgate.conf** | INI config file pointing to the dylib map. Generated by rotest at initialization. |
| **ASan shim** | No-op implementations of ASan runtime functions (`__asan_*`, `__sanitizer_*`) compiled into `libsystem_shim.so`. Allows ASan-instrumented binaries to run by mapping a zeroed shadow memory region. In progress on `feature/armando/asan-support`. |

## Platform detection

| Term | Definition |
|---|---|
| **Host architecture** | The CPU architecture of the machine running rotest. Determines whether MachGate runs natively (ARM64) or via QEMU (x86_64). rotest detects via `platform.machine()` or `os.uname().machine`. |
| **Execution strategy** | How rotest launches a Mach-O binary through MachGate: direct exec on ARM64, Docker container on x86_64. Selected automatically based on host architecture. |

## rotest integration points

| Term | File | Role |
|---|---|---|
| **Platform prefix** | `librotest/platform.py` | `make_executable_launch_command()` returns the MachGate prefix. Single chokepoint for both test execution and test discovery. |
| **Platform initializer** | `librotest/roconfig.py` | `--machgate` flag, parallel to `--android`/`--ios`. |
| **MachGate initializer** | `rotest.py` | `machgate_initialize()` generates config files, sets `LD_LIBRARY_PATH`, calls `platform.initialize_platform_cmd_prefix()`. |
| **Gobot platform** | `gobot_configs/os/machgate.yaml` | Platform definition with arch, options, env. |
| **Common-tests coverage** | `gobot_configs/projects/common-tests.yaml` | Adds `machgate` to platform/arch list for `*.UnitTest` and `UnitTests`. |

## Build pipeline

| Term | Definition |
|---|---|
| **Cross-compilation** | Building macOS/iOS ARM64 Mach-O binaries on a Linux host using the OSS LLVM Apple Clang toolchain. Activated by `xcode-toolchain=cross-compilation` in gobot. |
| **MachGate release tarball** | `machgate-X.Y.Z-linux-arm64.tar.gz` published by the GitHub release workflow. Contains `bin/machgate`, `lib/libsystem_shim.so`, `lib/libc++.so.1`, `lib/libc++abi.so.1`, `lib/libatomic.so.1`. |
| **TC build** | TeamCity build configuration that cross-compiles common-tests, downloads MachGate release, and runs rotest with `--machgate` on the ARM64 agent pool. |

## Relationships to existing glossary terms

| Existing term | MachGate relationship |
|---|---|
| **Executable** | The guest Mach-O binary. MachGate does not change what an Executable is. |
| **Driver definition** | Unchanged. The `rotest-config.json` entry still points to the Mach-O binary path. MachGate wraps execution, not configuration. |
| **Driver Format** | Unchanged. `boost`, `doctest`, `roblox-test` formats work as-is — MachGate transparently passes args through. |
| **ProcessLauncher** | MachGate is a ProcessLauncher variant. On ARM64: direct exec with machgate prefix. On x86_64: Docker container with machgate prefix. |
| **Scheduler Worker** | Unchanged. Workers don't know about MachGate. |
| **TestGroup** | Unchanged. Groups of test cases dispatched to an Executable. |
| **CpuSetAssignment** | Applies to the MachGate process, not the guest binary inside. On ARM64, the guest binary's threads run on the same CPU set as MachGate. |

## What MachGate does NOT introduce

- No new Driver Format
- No new scheduler mode
- No new Worker mode
- No new TestGroup semantics
- No new retry or discovery logic
- No new result parsing

MachGate is purely a **ProcessLauncher** concern — it changes how the
Executable is started, nothing else.
